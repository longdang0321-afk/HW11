# 삽입 정렬 vs 셸 정렬 비교 (Shell Sort Comparison)

> 삽입 정렬(Insertion Sort)과 셸 정렬(Shell Sort)의 **비교 횟수**를 데이터 크기별로 측정하고,
> 셸 정렬의 간격(gap) 수열(기본 n/2 수열, Knuth 수열)이 성능에 미치는 영향을 분석한 실험이다.

## 핵심 결과 요약

n = 20,000일 때의 총 비교 횟수는 다음과 같다.

| 방식 | 비교 횟수 | 삽입 정렬 대비 |
|---|---:|---:|
| Insertion Sort | 100,152,991 | 1배 |
| Shell Sort (Original, n/2) | 628,988 | 약 159배 적음 |
| Shell Sort (Knuth) | 562,599 | 약 178배 적음 |

- 삽입 정렬은 n이 2배가 되면 비교 횟수가 약 **4배**가 되고, 셸 정렬은 약 **2.16~2.배**가 된다.
- Knuth 수열은 모든 n에서 Original보다 약 **8~20%** 적게 비교했다.
  가장 큰 이유는 **단계 수가 적어서** 단계마다 드는 최소 비교 횟수의 합이 작았기 때문이다.

## 2. 비교한 알고리즘

세 알고리즘은 모두 `gap_insertion_sort(arr, n, gap)`을 공유한다.
이 함수는 `gap`만큼 떨어진 원소끼리 삽입 정렬을 수행한다.
한 번 호출하는 것을 **한 단계(pass)** 라고 부른다.

| 알고리즘 | 간격 수열 | 구현 |
|---|---|---|
| Insertion Sort | 1 | `gap = 1`로 한 번만 호출 |
| Shell Sort (Original) | n/2, n/4, ..., 1 | gap을 절반씩 줄이며 반복 호출 |
| Shell Sort (Knuth) | ..., 121, 40, 13, 4, 1 (`gap = 3*gap + 1`) | n보다 작은 가장 큰 Knuth 간격부터 3으로 나누며 반복 호출 |

## 3. 실험 방법

- 데이터 크기 `n`: 1000, 2000, 4000, 8000, 16000, 20000
- 데이터: `srand(2026)` 후 `rand() % 100000`으로 생성한 랜덤 정수
- **같은 원본 배열을 복사**해서 세 알고리즘이 동일한 입력을 정렬하게 했다.
- 비교 횟수: `arr[j]`와 `key`를 비교한 횟수 (결과가 참이든 거짓이든 모두 센다).
- 정렬 후 `is_sorted()`로 오름차순인지 검증했다.
- 데이터 크기마다 **한 번씩** 실행했다 (평균이 아님).

### 4.3 gap 수열에서 계산한 단계 수와 최소 비교 횟수

각 gap 단계에서는 인덱스 `gap`부터 `n-1`까지의 원소를 처리하며,
각 원소에 대해 적어도 한 번 값 비교가 발생한다.
따라서 한 단계의 최소 비교 횟수는 `n − gap`이고,
전체 최소 비교 횟수는 `Σ(n − gap)`이다.

> **계산 예 (n = 1000)**
> - Original: gap이 500, 250, 125, 62, 31, 15, 7, 3, 1 (9단계), gap의 합 994
>   → 최소 비교 = 9 × 1000 − 994 = **8,006**
> - Knuth: gap이 364, 121, 40, 13, 4, 1 (6단계), gap의 합 543
>   → 최소 비교 = 6 × 1000 − 543 = **5,457**

**추가 비교**는 총 비교 횟수에서 최소 비교 횟수를 뺀 값이다.
추가 비교는 원소 이동과 관련이 있지만, 실제 이동 횟수와 정확히 같지는 않다.

| 1,000 | Original | 9 | 8,006 | 6,785 | 14,791 |
| 1,000 | Knuth | 6 | 5,457 | 8,116 | 13,573 |
| 2,000 | Original | 10 | 18,006 | 18,917 | 36,923 |
| 2,000 | Knuth | 7 | 12,364 | 20,828 | 33,192 |
| 4,000 | Original | 11 | 40,006 | 46,651 | 86,657 |
| 4,000 | Knuth | 8 | 27,084 | 46,888 | 73,972 |
| 8,000 | Original | 12 | 88,006 | 113,440 | 201,446 |
| 8,000 | Knuth | 8 | 59,084 | 121,159 | 180,243 |
| 16,000 | Original | 13 | 192,006 | 297,052 | 489,058 |

## 5. 비교 및 분석

### 5.1 데이터 크기 증가에 따른 비교 횟수 변화

**삽입 정렬은 n²에 비례해서 증가했다.**
n이 2배가 될 때마다 비교 횟수가 약 4배가 되었다 (4.13 → 3.91 → 4.04 → 3.91배).
원소 하나당 비교 횟수(4.2)도 n에 거의 비례해서 커졌고(247 → 5,008),
`비교 횟수 / n²`는 모든 n에서 약 0.25로 일정했다.
랜덤 배열의 평균 역순쌍(inversion)이 약 n²/4개이고,
삽입 정렬은 원소를 한 칸씩만 옮기기 때문에 역순쌍 하나를 해결할 때마다 비교가 한 번 필요하기 때문이다.

**셸 정렬은 훨씬 느리게 증가했다.**
n이 2배가 될 때 비교 횟수는 약 2.2~2.5배만 늘었고,
원소 하나당 비교 횟수는 n이 20배로 커지는 동안
약 15 → 31 (Original), 14 → 28 (Knuth)로 두 배 정도만 늘었다.
n=1000과 n=16000의 결과로 증가 지수를 추정하면
(`log(비교 횟수 비) / log(n 비)`) 삽입 정렬 약 2.0, Original 약 1.26, Knuth 약 1.21이었다.
(데이터 크기마다 한 번씩만 측정한 추정치이므로 정확한 시간복잡도를 증명하는 것은 아니다.)

### 5.2 삽입 정렬과 셸 정렬의 성능 차이

n=20,000에서 삽입 정렬은 약 1억 번, 셸 정렬은 약 56만~63만 번 비교하여 **약 160~180배** 적다.
이 배율은 n=1000의 약 17~18배에서 n이 커질수록 계속 커졌다
(n=4000: 46.1/54.0배, n=16000: 129.4/162.3배, 각각 Original/Knuth).
삽입 정렬은 n²로, 셸 정렬은 그보다 느리게 증가하므로 n이 클수록 격차가 벌어진다.

**원인은 측정한 총 비교 횟수만으로도 추론할 수 있다.**
셸 정렬의 마지막 단계(`gap = 1`)는 삽입 정렬과 똑같은 알고리즘이다.
그 단계의 비교 횟수는 셸 정렬 전체 비교 횟수를 넘을 수 없다
(n=20,000에서 많아야 약 56만~63만, 원소당 28~31번).
그런데 같은 알고리즘이 무작위 배열을 처음부터 정렬하면 약 1억 번(원소당 5,008번)이 필요하다.
따라서 마지막 단계에 도달했을 때 배열의 역순쌍은 원본보다 훨씬 적어진 것으로 볼 수 있다.
앞의 큰 gap 단계들이 원소를 gap칸씩 한 번에 멀리 이동시켜 이 상태를 만든 것이다.
삽입 정렬은 원소를 한 칸씩만 옮기므로 멀리 떨어진 원소를 제자리로 보내려면 많은 비교가 필요하고,
셸 정렬은 이 비용을 큰 gap 단계에서 미리 줄여 둔다.

### 5.3 셸 정렬의 기본 간격(Original)과 Knuth 수열의 성능 차이

모든 n에서 Knuth가 Original보다 적게 비교했고, 감소 폭은 약 8~20%였다.

| n | 1,000 | 2,000 | 4,000 | 8,000 | 16,000 | 20,000 |
|---|---:|---:|---:|---:|---:|---:|
| Knuth의 감소 폭 | 8.2% | 10.1% | 14.6% | 10.5% | 20.3% | 10.6% |

감소 폭이 n에 따라 규칙적으로 늘지는 않았다.
차이가 어디서 생기는지 비교 횟수를 두 부분(4.3의 최소 비교와 추가 비교)으로 나눠서 확인했다.

| n | 전체 차이 (Original − Knuth) | 최소 비교의 차이 | 추가 비교의 차이 |
|---:|---:|---:|---:|
| 1,000 | 1,218 | 2,549 | −1,331 |
| 2,000 | 3,731 | 5,642 | −1,911 |
| 4,000 | 12,685 | 12,922 | −237 |
| 8,000 | 21,203 | 28,922 | −7,719 |
| 16,000 | 99,065 | 62,763 | +36,302 |
| 20,000 | 66,389 | 94,762 | −28,373 |

- 이번 실험에서 Knuth는 Original보다 단계 수가 적었고,
  그에 따라 각 단계의 최소 비교 횟수 합계도 작았다.
  예를 들어 n=16,000에서는 최소 비교 횟수의 차이가 62,763회였다.
- 추가 비교 횟수는 n=16,000에서는 Knuth가 더 적었지만,
  나머지 다섯 크기에서는 Knuth가 더 많았다.
  따라서 이번 결과에서는 단계 수에 따른 최소 비교 횟수의 차이가
  Knuth의 총 비교 횟수를 줄이는 데 크게 기여했다고 볼 수 있다.

### 5.4 간격 수열이 셸 정렬의 성능에 영향을 미치는 이유

셸 정렬은 여러 gap을 적용하며 배열을 점차 정리한다.
어떤 gap을 선택하느냐에 따라 각 단계에서 비교하고 이동하는 원소들의 위치가 달라지므로
전체 비교 횟수에도 차이가 생긴다.

각 gap 단계에서는 인덱스 `gap`부터 `n-1`까지의 원소를 처리한다.
각 원소에 대해 적어도 한 번의 값 비교가 발생하므로 한 단계의 최소 비교 횟수는 `n − gap`이다.
따라서 전체 최소 비교 횟수는 **단계 수**와 **각 gap의 크기**에 영향을 받는다.

이번 실험에서는 Knuth 수열의 단계 수가 Original보다 적었고, 최소 비교 횟수의 합계도 더 작았다.
반면 최소 비교 횟수를 제외한 추가 비교 횟수는 6개 크기 중 5개에서 Knuth가 더 많았다.
이는 단계 수가 적더라도 각 단계에서 발생하는 비교가 많아질 수 있음을 보여 준다.

즉, 간격 수열에 따라 단계 수와 각 단계에서 필요한 비교 횟수가 달라진다.
이번 데이터에서는 Knuth 수열의 최소 비교 횟수가 더 적었던 효과가 커서
총 비교 횟수도 Original보다 적었다.

참고로 Original 수열에는 약수·배수 관계인 간격이 많고,
Knuth 수열의 인접한 간격은 `gcd(3g+1, g) = 1`이므로 서로소이다.
이러한 간격의 관계는 각 단계에서 어떤 위치의 원소들이 비교되는지에 영향을 줄 수 있다.
다만 이번 실험에서는 gap 단계별 비교 횟수와 원소 이동 횟수를 측정하지 않았으므로,
이러한 관계가 결과에 미친 영향을 직접 확인하지는 못했다.

## 6. 한계

- 데이터 크기마다 **한 번만** 실행했으므로 평균이 아니다. 시드를 바꾸면 값이 달라질 수 있다.
- gap 단계별 비교 횟수는 측정하지 않았으므로, 간격 수열이 단계마다 일을 어떻게 나누는지는 직접 확인하지 못했다.
  (단계 수와 최소 비교는 gap 수열에서 계산한 값이다.)
- 랜덤 데이터만 사용했다. 정렬된 데이터, 역순 데이터에서는 결과가 다를 수 있다.
- 측정한 것은 **비교 횟수**뿐이다. 실제 실행 시간이나 정확한 이동 횟수는 측정하지 않았다.
  ("추가 비교"는 이동량에 가까운 값이지만 이동 횟수와 완전히 같지는 않다.)
- `rand()`의 구현은 컴파일러/OS마다 달라서, 다른 환경에서는 숫자가 달라질 수 있다.
  같은 환경에서는 시드가 고정되어 있어 항상 같은 결과가 나온다.

## 7. 결론

1. 삽입 정렬의 비교 횟수는 약 n²/4로, n이 2배가 되면 약 4배가 된다.
   셸 정렬은 약 2.2~2.5배로 훨씬 느리게 증가한다.
2. 셸 정렬이 삽입 정렬보다 약 17~178배 적게 비교한 이유는,
   큰 gap 단계들이 데이터를 거의 정렬된 상태로 만들어 마지막 `gap = 1` 단계의 비용이 크게 줄었기 때문이다.
3. 이번 실험에서 Knuth 수열은 Original보다 모든 n에서 약 8~20% 적게 비교했다.
   Knuth는 단계 수가 적어 최소 비교 횟수의 합계가 작았으며,
   추가 비교 횟수는 n=16,000을 제외한 나머지 크기에서 더 많았다.
4. 간격 수열은 단계 수와 각 단계에서 필요한 비교 횟수에 영향을 주므로
   같은 셸 정렬이라도 총 비교 횟수가 달라진다.
